# 2026-11-12

**Done:**
- Rewrote the NEAR contract from scratch in [contract/src/lib.rs](../../contract/src/lib.rs). It's built around runs and replaces the old `write_receipt` contract.
  - `Label`: True, False, Misleading, Unverified, Contested
  - `Status`: `Pending`, `Verdict(Label)`, `Abandoned`, `Late(Label)`
  - `Run`: `id`, `claim_post_id`, `claim_hash`, `jury_config`, `registered_at_ms`, `status`, `receipt_cid`, `verdict_at_ms`
  - `register_claim`: triage only; creates a Pending run; rejects a reused `run_id`
  - `submit_verdict`: jury only; one verdict per run; after the timeout it's stored as `Late`
  - Views: `get_run`, `get_runs_by_post` (all runs for a post, oldest first, abandoned ones included), `get_timeout_ms`
  - `Abandoned` is never stored. A view shows a run as Abandoned when it's still Pending past the timeout, so no scheduled job is needed.
- 8 unit tests in [contract/src/tests.rs](../../contract/src/tests.rs), all passing

**Interface changes:**
- Final contract interface (replaces the §4 draft):

  ```
  register_claim(run_id, claim_post_id, claim_hash, jury_config)   // signer: triage
  submit_verdict(run_id, label, receipt_cid)                       // signer: jury
  get_run(run_id) -> Run | null
  get_runs_by_post(claim_post_id) -> Run[]
  get_timeout_ms() -> number
  ```

  - All arguments are strings. `label` is one of `"True"`, `"False"`, `"Misleading"`, `"Unverified"`, `"Contested"`.
  - `status` comes back as `"Pending"`, `"Abandoned"`, `{"Verdict": "False"}` or `{"Late": "True"}`.
  - Errors (the transaction fails): `only triage can register claims`, `run_id already exists`, `only jury can submit verdicts`, `run not found`, `verdict already exists for this run`.
  - `attach_sources` and the claim-hash view are not in this version.
